# Source and freshness policy

## Source hierarchy

1. Provider-controlled pricing or plan page.
2. Provider-controlled product documentation describing the exact free quota.
3. Provider-controlled terms, acceptable-use, billing, regional, privacy, or support documentation.
4. Current free-for.dev README for discovery.
5. Third-party reporting only when the provider has no accessible primary source, clearly labeled as secondary.

## Claim labels

- `catalog-only`: present in free-for.dev but not checked against the provider.
- `partially verified`: some material terms are confirmed, but one or more decision-critical terms remain unknown.
- `verified`: current provider-controlled sources confirm the relevant quota, duration, eligibility, and material billing behavior.
- `conflict`: catalog and provider sources disagree. Use the provider source and state the conflict.
- `unavailable`: the provider page or service cannot be confirmed.

## Freshness rules

Free-tier pricing is volatile. Re-verify whenever the user asks for current, latest, best, cheapest, no-card, commercial-use, regional, or production suitability. Record the verification date in an absolute date format.

## Required caveat

A free tier is not a guarantee of zero cost. Billing can arise from overages, egress, add-ons, taxes, payment verification, resource combinations, or automatic conversion to paid usage.
