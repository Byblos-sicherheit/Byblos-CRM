# Routing contract

## Intents

- `discover`: find candidate services.
- `compare`: rank known candidates.
- `verify`: confirm provider-controlled facts.
- `stack`: assemble a multi-service stack.
- `architecture`: evaluate topology, dependencies, and failure domains.
- `cost`: model free allowance headroom and paid transition.
- `compliance`: filter on EU/privacy/business evidence.
- `risk`: review billing, operational, security, privacy, and lock-in risks.
- `alternatives`: find substitutes.
- `migrate`: plan a source-to-target migration.
- `diff`: compare historical snapshots.
- `watch`: evaluate or configure material-change monitoring.
- `profile`: build an evidence dossier for one provider/service.
- `export`: create structured output files.

## Constraint classes

Hard constraints must be enforced before scoring. Common hard constraints include explicit no-card requirements, region restrictions, non-trial requirements, commercial-use requirements, and maximum spend.

Preferences affect ranking only. Examples include simplicity, generous quota, low lock-in, developer experience, and breadth of integrations.

## Evidence routing

Catalog text is discovery evidence only. Current quotas, prices, billing triggers, card requirements, regions, terms, privacy documents, and commercial restrictions require provider-controlled verification when material to a decision.
